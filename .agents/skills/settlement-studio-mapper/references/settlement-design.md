# 从粗略输入到合理的聚落布局

## 适用的两种入口

- **资料驱动**：从故事、方志或城市设定中找出必须实现的空间关系，再补足普通生活和生产所需的背景。
- **环境驱动**：从坐标/区域、气候、地形、重要性出发，自主选择适合的聚落身份和结构。没有故事、专名或详尽历史不妨碍生成。

用户指定的形态和想象优先；粗略输入不足以确认的内容，以本次设计选择呈现。经纬度不单独决定气候，区域平均高程也不是每座山坡的实测高度。

## 先写足够短的设计简报

通常几句话或一张小表足够，复杂城市才展开：

1. **身份与规模**：谁住这里，它在区域中承担什么作用？规模取合理范围即可。
2. **形成原因**：水源、可耕地、渡口、港湾、矿业、行政或其他条件中，哪几项最重要？
3. **地方骨架**：主谷/河阶/山坡怎样限制建设；核心、增长方向和主要通路如何安排？
4. **日常使用**：供水、进出、交易、生产/耕作如何联系？谁使用生产用地、住在哪里、怎样往返？精度以图幅尺度为准。
5. **变化范围**：哪些是已知要求，哪些是推定，这次在哪些部分进行抽卡？

此简报用于后续实际制作。避免只列“河流、城墙、住宅、农田”等对象名而不说明它们的关系。普通任务自主选定方案继续，不把简报变成额外审批环节。

## 合理抽卡：在条件内选择，而非逐项独立随机

先选择一套相互兼容的布局，再选择局部细节。可以由模型提出少量候选并自主挑选；用户指定数量时按其要求生成。不需要实现概率引擎或假装模型的选择来自精确统计分布。

| 选择 | 受什么影响 | 可以产生的变化 |
| --- | --- | --- |
| 聚落主业/身份 | 区位、资源、既定文化、城市重要性 | 农业集镇、区域行政中心、渡口贸易镇、矿业服务镇等，可兼有次要用途 |
| 水源与建设位置 | 地形、气候、沿海/内陆、水系 | 河阶、井泉核心、湖岸高地、谷口扇缘；不同条件允许不同设施 |
| 聚落结构 | 地形、主要路线、用途与形成过程 | 沿路延展、沿河带状、节点汇聚、多核心、跨河扩展 |
| 街区与边缘 | 核心年代、对外路线、空地与生产空间 | 旧核心紧凑、新区疏松、沿街院落、外围散居 |
| 局部细节 | 已确定的骨架与尺度 | 房屋/田地/树木 seed、区块轮廓、少量密度和方向差异 |

把主要选择记录下来。局部重抽保留核心、水源和主要通路；整体变体可以改变增长结构，但仍遵守相同环境约束。批量生成时变化聚落的形成原因和结构，避免只换屋宇 seed。

## 让空间选择有原因

- 城市或小镇从吸引人留下的条件开始布置；重要性不直接等于城墙规模。
- 先安排公共活动、货物进出和生产所需空间，再用住宅填充适合的部分。
- 道路有目的地，田地有接近方式，水线有来去方向；在地图精度允许的程度上交代即可。
- 考虑明显的上下游、高低地、陡缓坡和干湿差异。不需要模拟经济、交通或流体全过程。
- 主要城市可以有旧核心、次级市场、外围生产区等多个中心；仅在用途支持时选用这些内容。
- 开放聚落、围墙镇、院落堡寨是不同选择。不要把普通行政建筑强行做成封闭堡寨，也不要把一个设施放进每张图作为标配。
- 工具 primitive 是表达手段。`market` 可以表示一块交易场，`exclusion` 可以留出空地；给它们的实际用途取合适名字。

例如：一座半干旱内陆山前镇，可以依泉井和山前道路形成紧凑核心，耕地集中在可获得水的扇缘，外围较疏。它也可以在常流河阶上形成沿河街区；选择哪种，应与本次地域信息一致，而非同时添加所有水源类型。

## 生产用地与居住空间一起设计

农田、作坊、牧地等由人使用。安排这些空间时，同时考虑使用者的住处与日常往返，让生产区嵌在地方生活中。

对农田可以选择不同关系，并允许同图并存：
- **近郊耕作**：由镇边居民出田，住宅、院落、菜园与大田逐渐过渡；不必另设一座村。
- **村落耕作**：较远田片可由沿田径、水源或地形节点形成的小村共同使用；多片田可以共用一个聚落。
- **散居农户**：少量农舍带院场、储物/牲畜棚及菜畦，适合分散田片；无需为了几户人调用一个密集村落模板。

依据地方生活方式、地形与可达距离选择，不把分散居住或集村耕作当成所有地域的定律。住房通常可占田边较干燥的缓坡、路边或台地，保留好耕地的连续性，并避开明显的易淹低地。

### 农舍到田地的距离

安排农居时，简短明确它主要服务哪些田片；一个村落可联系多片田，不必逐户划定产权。先由使用关系决定选址，再生成房屋与田地细节。

- **菜园与频繁照料的用地优先近宅**：让住宅、院场和菜畦直接衔接，方便取水、照料、采收及使用家庭资源。
- **主要耕地优先便于日常往返**：普通农舍可位于田边，集村则组织通往各主要田片的短田径。比较少量代表路线，粗看绕行、上下坡，以及携带农具、运肥和收获搬运的负担。
- **区分三种距离**：到整片田区边缘、到具体耕作位置、沿实际田径走到那里，含义不同。附近有一栋房或距离田边很近，并不自动说明经营者的日常路线合理。
- **远田需要符合地方条件**：集村制度、零散经营或地形限制下可以有远田，必要时采用共用棚场或田间储物设施。不把少数远田当作全图默认，也不为每片较远田强行加村。

这些是模型布置时的设计偏好，不设所有地域通用的米数上限，不要求完整的耕作、产权或通勤模拟。粗略地图交代主要农居—田片关系即可。

现实参考及适用范围：
- [FAO《Livelihoods grow in gardens》布局章节](https://www.fao.org/4/y5112e/y5112e05.htm)：屋旁菜园便于浇水、施肥、采收和利用家庭资源。此依据针对家庭园圃，不表示所有主粮田必须贴屋。
- [Historic England《National Farmsteads Character Statement》“Outlying field barns and outfarms”](https://historicengland.org.uk/images-books/publications/national-farmsteads-character-statement/national-farmsteads-character-statement/)：记载英国部分谷地农场与高地田块相距一英里以上，以及用田间设施减少运输的方式。属于特定历史地区的实例，不是通用布局目标。
- [Su等（2022），贵州白渡村住址—耕地研究](https://www.frontiersin.org/journals/environmental-science/articles/10.3389/fenvs.2022.1017599/full)：结合道路和坡度讨论耕作往返；研究报告较长的耕作路程及较高通勤成本。现实存在远田，不代表它是理想安排，也不能将这个山地村的数值推广为所有地方的阈值。

按需要补充取水点、晒场、棚舍或储粮空间。可以共享现有设施；不要给每户、每块田复制一套完整配置。将田径接到聚落小路和对外通路；饮用取水与明显的牲畜污水位置应相称。

用少量显式建筑表达散居农家，用适合的选区和路径组织成村住房。观察实际产物：几户农家不应意外长成密集环状营地。调整农业居住空间时，也应重看周边田地，避免屋舍与农田互相覆盖。

## 制作中保持构想

从环境与对外通路开始，再做核心、功能区、住宅和土地利用。每次增加内容时问：它为什么在这里，与已有内容通过什么联系？

布局不合适时改骨架或选区；只有局部排布不满意时才重抽。不要用更密的房屋、更大的树林或更多地标掩盖结构空缺。也不要为了“自然”故意破坏已有的功能关系。

选择适合任务的图幅，不必让主城占固定百分比。单城详图与包含远郊/山路的地区图，需要不同范围；比较迭代时说明范围或尺度变化。

## 轻量复查

看实际预览并选两三种相关活动，例如货物进市、居民取水、居民出田、人员进出公共院落。只需指出具体的使用路径和明显矛盾，有问题用现有操作修正。

必要时查询少量关键点的高程/坡度或对象位置。现有工具的零碰撞/空区提示有辅助价值，但不替代这次空间判断。不引入复杂新校验系统，也不为了凑检查次数而反复折腾已经合适的图。

交付说明以“做出了怎样的地方、主要选择为何合理”为主。复杂任务保存简报与操作批次便于复用；简单任务不必增加配套文件。
